# اتفاقيات مشروع EOMS

## البنية
- كل وحدة في `app/Modules/<Name>` وتحوي: Models و Services و Http و Database و Routes و Providers و Policies.
- الوحدات تشترك في قاعدة بيانات واحدة، ولكل وحدة بادئة جداول خاصة (usr_ و hr_ و pay_ ...).
- لا تقرأ وحدة جداول وحدة أخرى مباشرة. التواصل يكون عبر Services أو Events.

## التدفق
- Controller: يستقبل الطلب ويُرجع الاستجابة فقط.
- FormRequest: يتحقق من المدخلات.
- Service: يحوي قواعد العمل والمعاملات (Transactions) والتدقيق.
- Model: البيانات والعلاقات والـ casts فقط.
- ممنوع الاستعلام المباشر داخل Controller.

## تسمية الصلاحيات
- بصيغة `الوحدة.الإجراء` مثل `employees.view` و`payroll.approve`.

## شكل الاستجابة (API)
- البادئة: `/api/v1`.
- النجاح: `{ "data": ... }`، ومع الترقيم: `{ "data": [...], "links": {...}, "meta": {...} }`.
- الخطأ: `{ "message": "...", "errors": { "field": ["..."] } }` (errors اختيارية).
- الحالات: 200 للقراءة، 201 للإنشاء، 401 لغير المسجل، 403 لغير المخوّل، 404 غير موجود، 422 للتحقق.
- التواريخ بصيغة ISO 8601.

## التدقيق
- كل عملية حساسة (إنشاء، تعديل، اعتماد، صرف، تغيير صلاحية) تُسجَّل عبر `AuditLogger`.
- لا تُسجَّل كلمات المرور أبداً.

## الاختبارات
- كل Service له اختبارات Feature تغطي الصلاحيات والحالات الفاشلة.
- اختبارات الوحدات تعمل على `eoms_test` فقط.

## قواعد عامة
- لا قيم ثابتة في الكود، وتُقرأ من `.env` عبر `config/`.
- لا أسرار في Git.
